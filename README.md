# tvissn — совместный просмотр через P2P

Расширение Chrome/Chromium для двух участников. Собственного сервера, signaling-сервера, прокси и базы данных в приложении больше нет. Каждый смотрит видео с исходного сайта; между расширениями идут только команды и состояние по зашифрованному WebRTC DataChannel.

## Подключение

1. Оба устанавливают одинаковую новую версию расширения из [GitHub Releases](https://github.com/tuturuleo/tvissn/releases/latest).
2. Первый вводит имя и нажимает «Создать новый код». Отправляет полученный код другу в мессенджере.
3. Друг вводит имя, вставляет первый код и нажимает «Принять код и создать ответ». Отправляет ответный код обратно.
4. Первый вставляет ответ и нажимает «Завершить подключение».
5. После появления P2P-соединения откройте страницу с видео и нажмите «Смотреть в этой вкладке» в расширении. При необходимости разрешите iframe и повторите поиск плеера.

Коды действуют до 30 минут, относятся к одному подключению и содержат сетевые параметры. Делитесь ими только с другом. Старые ссылки и серверные приглашения больше не используются. После перезагрузки браузера/расширения или потери связи создайте новое подключение. Закрытие popup и переходы между видео сами по себе не закрывают соединение: оно хранится в offscreen-документе Chrome с причиной WEB_RTC.

### Обмен через сервер (необязательно)

В «Настройках» popup можно включить «Обмен кодами через сервер» и указать ntfy-сервер (по умолчанию `https://ntfy.sh`, подойдёт и свой ntfy). Тогда первый участник получает короткий код комнаты вида `tvissn-room:ABCD-EFGH-JKMN@ntfy.sh`, друг вставляет его в то же поле, и ответный код передаётся автоматически за секунду. Сервер видит только топик-хеш и зашифрованные AES-GCM коды; ключ есть только в коде комнаты. Если сервер недоступен, в popup остаётся ручной код.

При ручном обмене ответный код нужно вернуть быстро: сторона, создавшая ответ, сразу начинает проверку маршрутов, и Chrome сдаётся примерно через 30 секунд. Расширение держит эту сторону живой до истечения кода, но быстрый обмен или сервер надёжнее.

Проверка доступности ntfy.sh: страница https://ntfy.sh/v1/health должна показать `{"healthy":true}`.

### Режим отладки

В «Настройках» включается «Режим отладки»: popup показывает диагностику P2P (тип NAT, время сбора кандидатов, время до сбоя ICE, ошибки STUN, состояние сервера обмена) и кнопку её копирования. Если NAT симметричный, предупреждение показывается и без отладки.

## Возможности

- Оба участника могут менять общее видео, включать паузу, перематывать и менять скорость. Создатель подключения лишь упорядочивает команды.
- Участники и RTT между устройствами отображаются в popup.
- Перетаскиваемый минивиджет с сохранением позиции, паузой и ±10 секунд в обоих размерах, синхронизацией, fullscreen и локальной громкостью.
- Автоскрытие через 2 секунды, плавное исчезновение и настройка reduced motion.
- Повторный поиск/выбор плеера и опциональный автопереход подключённой вкладки за общим видео.
- Код расширения и автоматический выпуск ZIP находятся в этом репозитории.

Используются публичные STUN Google и Cloudflare для поиска прямого маршрута; они не являются signaling и не пересылают команды. TURN не используется. В некоторых сетях прямое соединение невозможно — в этом случае нужны другая сеть или VPN. P2P раскрывает сетевой адрес собеседнику. Доступность самих видеосайтов расширение не меняет.

## Установка и обновления

Распакуйте ZIP в постоянную папку, включите режим разработчика на chrome://extensions и загрузите распакованное расширение. При обновлении замените файлы **в той же папке** и нажмите Reload. Не удаляйте расширение перед обновлением. Стабильный ID: `fkohpgglbodngaicfehkgdojlbgpbijo`; ключ в extension/identity.json не меняется.

ZIP автоматически публикуется в GitHub Releases после push в main. Popup проверяет последний выпуск публичного репозитория через GitHub API (не чаще раза в 30 минут, кнопка «Проверить обновления» — принудительно) и при наличии новой версии показывает «Скачать обновление»: ZIP сохраняется в загрузки. Распакованное расширение Chrome не обновляет само — распакуйте архив в ту же папку с заменой файлов и нажмите Reload. Старые адреса Render/Cloudflare больше не используются.

## Разработка

Node.js >=22.12, `npm ci`, `npm test`, `npm run build`.

Результаты: extension-dist/ (загрузка в Chrome) и dist/extension/tvissn-extension.zip.

Автоматические тесты проверяют протокол/устаревшие команды, оба offscreen-runtime через имитацию RTC и Chrome RPC, обмен кодами, подтверждения, разрыв соединения, работу виджета и выбор плееров. Они не заменяют проверку настоящего ICE/NAT между двумя сетями.

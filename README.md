# tvissn

Приватный совместный просмотр YouTube. Одна комната, вход по коду, одинаковые права управления у всех участников. Без регистрации, чата, звонков и очереди.

## Локальный запуск

Нужен Node.js 24 (или 22.12+).

```sh
npm ci
cp .env.example .env
# Укажите собственный INVITE_CODE в .env.
npm run dev:server
# В другом терминале:
npm run dev
```

Откройте http://localhost:5173. При локальной разработке без DATABASE_URL состояние хранится в `.data/state.json`. `.env` и `.data` не попадают в Git и Docker-образ.

```sh
npm test
npm run build
```

## Развёртывание через AppHub

Проект `tvissn`, рецепт `docker-postgres`: приватный репозиторий GitHub, Docker на Render, PostgreSQL в Supabase. Render собирает Dockerfile после изменения основной ветки. Контейнер слушает `PORT` и отвечает на `/health`. Один процесс обслуживает API, Socket.IO и собранный React-клиент.

- `DATABASE_URL` — секрет подключения, настроенный AppHub. Обязателен в production.
- `RENDER_EXTERNAL_URL` — устанавливается Render; используется для проверки Origin.
- `APP_ORIGIN` — необязательный список разрешённых origin через запятую. Укажите при добавлении своего домена, например `https://watch.example.com`.
- `INVITE_CODE` — необязательный новый код (минимум 8 символов, рекомендуются 16 случайных). Если не задан, сервер проверяет первоначальный случайный код по SHA-256 verifier в `server/invite-config.ts`. Исходный код приглашения не хранится в репозитории и передаётся владельцу отдельно.
- `SESSION_SECRET` — необязательный отдельный секрет подписи cookie. Без него ключ получается из секрета DATABASE_URL и verifier кода. Для принудительного отзыва всех сессий измените SESSION_SECRET и передеплойте.

Встроенный первоначальный verifier позволяет запустить приложение без ручной настройки секрета в AppHub, сохраняя код приглашения вне исходников. Для ротации предпочтительно задавать INVITE_CODE в окружении сервиса. Смена кода меняет автоматически полученный ключ cookie; если SESSION_SECRET задан отдельно, для отзыва существующих сессий меняйте и его.

Миграции из `migrations/` применяются транзакционно при старте, с журналом `_migrations` и advisory lock. Применённые миграции не редактировать. `0001_notes.sql` сохранена из рецепта AppHub, `0002_tvissn.sql` добавляет состояние просмотра и закрывает его от публичного Supabase Data API с помощью RLS. Неиспользуемый Python-шаблон удалён.

Не масштабировать больше одного процесса без общего механизма синхронизации: состояние и подключения одной комнаты принадлежат одному процессу. На бесплатном Render возможен холодный старт после простоя и обрывы при деплое; клиент переподключается автоматически. Приложение не зависит от AppHub во время просмотра и переносится как обычный Docker-образ с PostgreSQL.

## Как синхронизируется просмотр

Сервер последовательно применяет команды, проверяет действительность сессии, версии медиа и commandId. Каждый snapshot содержит время сервера, положение, скорость, версию состояния и участников. Клиент оценивает смещение часов через ping/pong. Поздний вход получает актуальный snapshot. Программные действия плеера подавляют обратную отправку событий; native play/pause/seek также синхронизируются. При обрыве связи локальный плеер ставится на паузу и возвращается к общей позиции после восстановления.

Видео загружается непосредственно из YouTube у каждого зрителя, не проходит через наш сервер. Поддерживаются обычные записи и ссылки watch/youtu.be/shorts/embed/live; стабильная синхронизация прямых эфиров не входит в гарантии MVP. Запрещённые для встраивания ролики показывают ошибку. Автозапуск со звуком может потребовать отдельного клика участника. Реклама и ограничения доступа YouTube могут временно нарушать синхронизацию: кнопка «Синхронизировать мой плеер» применяет общую позицию повторно.

Состояние сохраняется при командах и каждые 15 секунд. После рестарта восстанавливается в паузе с последней сохранённой позиции. Сессии действуют 7 дней, cookie HttpOnly/SameSite/Secure в production. Приглашение защищено ограничением попыток; секреты не пишутся в журнал.

## Резервная копия и перенос

Сохраните секреты окружения отдельно от исходников. Для базы используйте `pg_dump` с DATABASE_URL из защищённого окружения, для восстановления — `psql`/`pg_restore` на новом PostgreSQL. DATABASE_URL не вставляйте в код или публичную командную строку. После переноса укажите новый APP_ORIGIN и код приглашения; при изменении DATABASE_URL автоматически выданные ранее сессии становятся недействительны.

## Проверка MVP

1. В двух браузерах войти под разными именами с одним кодом.
2. Проверить неверный код, выход и запрет доступа к API/Socket.IO без сессии.
3. Вставить доступную для embed ссылку YouTube. Нажать play, pause и перемотать в каждом браузере по очереди.
4. Подключить третий браузер в середине просмотра и проверить текущую позицию.
5. Обновить страницу, отключить сеть и восстановить её.
6. Проверить мобильную ширину, клавиатуру (Space, стрелки ±10 секунд) и локальные звук/полноэкранный режим.
7. Перезапустить сервер: видео должно восстановиться в паузе.

Внешние сайты через расширение запланированы отдельным следующим этапом; в этот MVP они не входят.

## UI

React + Vite + Tailwind CSS. Компоненты shadcn/ui (new-york, zinc) находятся в `src/components/ui`, primitives — Radix UI. Русский интерфейс, тёмная тема, адаптивная компоновка, reduced-motion, подписи элементов и видимый фокус. Собственные шрифты/CDN не требуются.

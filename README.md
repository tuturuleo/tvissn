# tvissn — совместный просмотр через P2P

Расширение Chrome/Chromium для двух участников. Собственного сервера, signaling-сервера, прокси и базы данных в приложении больше нет. Каждый смотрит видео с исходного сайта; между расширениями идут только команды и состояние по зашифрованному WebRTC DataChannel.

## Подключение

1. Оба устанавливают одинаковую новую версию расширения из [GitHub Releases](https://github.com/tuturuleo/tvissn/releases/latest).
2. Первый вводит имя и нажимает «Создать новый код». Отправляет полученный код другу в мессенджере.
3. Друг вводит имя, вставляет первый код и нажимает «Принять код и создать ответ». Отправляет ответный код обратно.
4. Первый вставляет ответ и нажимает «Завершить подключение».
5. После появления P2P-соединения откройте страницу с видео и нажмите «Смотреть в этой вкладке» в расширении. При необходимости разрешите iframe и повторите поиск плеера.

Коды действуют до 30 минут, относятся к одному подключению и содержат сетевые параметры. Делитесь ими только с другом. Старые ссылки и серверные приглашения больше не используются. После перезагрузки браузера/расширения или потери связи создайте новое подключение. Закрытие popup и переходы между видео сами по себе не закрывают соединение: оно хранится в offscreen-документе Chrome с причиной WEB_RTC.

### Обмен через сервер (необязательно)

В «Настройках» popup можно включить «Обмен кодами через сервер» и указать сервер: MQTT-брокер через WebSocket (`wss://…`, по умолчанию `wss://broker.emqx.io:8084/mqtt`) или ntfy (`https://ntfy.sh`, `https://ntfy.envs.net` или свой ntfy). Для MQTT приглашение хранится как retained-сообщение, для ntfy — в истории топика. Тогда первый участник получает короткий код комнаты вида `tvissn-room:ABCD-EFGH-JKMN@wss://broker.emqx.io:8084/mqtt`, друг вставляет его в то же поле, и ответный код передаётся автоматически за секунду. Сервер видит только хеш-топик и зашифрованные AES-GCM коды; ключ есть только в коде комнаты. Если сервер недоступен, в popup остаётся ручной код.

При ручном обмене ответный код нужно вернуть быстро: сторона, создавшая ответ, сразу начинает проверку маршрутов, и Chrome сдаётся примерно через 30 секунд. Расширение держит эту сторону живой до истечения кода, но быстрый обмен или сервер надёжнее.

Проверка доступности ntfy.sh: страница https://ntfy.sh/v1/health должна показать `{"healthy":true}`.

### Свой сервер обмена на Windows

В [relay-server/windows](relay-server/windows) лежит скрипт, который поднимает ntfy за HTTPS-прокси Caddy как службы Windows. Скачайте оба файла в одну папку и дважды щёлкните `tvissn-relay.cmd` — откроется меню (права администратора запросятся сами). То же из командной строки:

```
tvissn-relay.cmd install                       # белый IP определится сам, адрес https://1-2-3-4.nip.io
tvissn-relay.cmd install -Dns sslip            # https://1-2-3-4.sslip.io
tvissn-relay.cmd install -Dns duckdns -DuckDnsDomain имя -DuckDnsToken токен
tvissn-relay.cmd install -Dns custom -Domain relay.example.com
tvissn-relay.cmd install -PublicIp 1.2.3.4 -Manual -Upnp
tvissn-relay.cmd status | start | stop | enable | disable | check | logs | update | uninstall
```

- `install` скачивает ntfy и Caddy с GitHub с проверкой контрольных сумм, пишет конфигурацию, регистрирует службы `tvissn-ntfy` и `tvissn-caddy`, правило брандмауэра для 80/443 и ждёт сертификат. Повторный `install` меняет настройки, остальное сохраняется.
- `enable` — автозапуск вместе с Windows, `disable` — остановить и не запускать, `start`/`stop` — разово.
- `check` — диагностика без установки: белый ли IP, нет ли CGNAT, разрешаются ли nip.io/sslip.io, свободны ли порты.
- Задача планировщика каждые 10 минут проверяет внешний IP: обновляет DuckDNS или переводит адрес nip.io/sslip.io на новый IP. Код комнаты содержит адрес на момент создания, поэтому смена IP между подключениями ничего не ломает.
- Сервер по умолчанию обслуживает только топики расширения (`tvissn_*`); `-OpenTopics` снимает ограничение.

Нужны белый IP (не CGNAT) и проброс TCP 80 и 443 на роутере на этот компьютер (или `-Upnp`). nip.io и sslip.io не входят в Public Suffix List, поэтому лимит Let's Encrypt для них общий у всех пользователей; если он исчерпан, Caddy сам выпустит сертификат через ZeroSSL. DuckDNS такой проблемы не имеет. Друг проверяет доступность адресом `https://<адрес>/v1/health`.

### Режим отладки

В «Настройках» включается «Режим отладки»: popup показывает диагностику P2P (тип NAT, время сбора кандидатов, время до сбоя ICE, ошибки STUN, состояние сервера обмена) и кнопку её копирования. Если NAT симметричный, предупреждение показывается и без отладки.

## Возможности

- Оба участника могут менять общее видео, включать паузу, перематывать и менять скорость. Создатель подключения лишь упорядочивает команды.
- Участники и RTT между устройствами отображаются в popup.
- Перетаскиваемый минивиджет с сохранением позиции, паузой и ±10 секунд в обоих размерах, синхронизацией, fullscreen и локальной громкостью.
- Автоскрытие через 2 секунды, плавное исчезновение и настройка reduced motion.
- Повторный поиск/выбор плеера и опциональный автопереход подключённой вкладки за общим видео.
- Код расширения и автоматический выпуск ZIP находятся в этом репозитории.

Используются публичные STUN Google и Cloudflare для поиска прямого маршрута; они не являются signaling и не пересылают команды. TURN не используется. В некоторых сетях прямое соединение невозможно — в этом случае нужны другая сеть или VPN. P2P раскрывает сетевой адрес собеседнику. Доступность самих видеосайтов расширение не меняет.

## Установка и обновления

**Windows.** Скачайте `tvissn-extension-setup.exe` из [GitHub Releases](https://github.com/tuturuleo/tvissn/releases/latest) и запустите самостоятельно. Права администратора не нужны. По умолчанию файлы попадут в постоянную папку `%LOCALAPPDATA%\tvissn\extension`; можно выбрать другую. При первой установке откройте chrome://extensions, включите режим разработчика, нажмите **Load unpacked / Загрузить распакованное расширение** и выберите показанную установщиком папку.

Если tvissn уже установлен вручную из ZIP, при первом запуске установщика выберите **точно прежнюю папку с manifest.json**, которую загружали в Chrome. Не переносите её и не удаляйте расширение из браузера. Для обновления запускайте установщик новой версии: он запоминает выбранный путь и заменяет только файлы пакета, не очищая постороннее содержимое. После установки нажмите **Reload / Обновить** у tvissn на chrome://extensions. ID и настройки сохраняются при использовании прежней папки и без удаления расширения.

**Другие системы и ZIP.** Распакуйте `tvissn-extension.zip` в постоянную папку и подключите через Load unpacked в режиме разработчика. Для обновления распакуйте новый ZIP **в ту же папку** с заменой файлов и нажмите Reload. Не удаляйте расширение. Стабильный ID: `fkohpgglbodngaicfehkgdojlbgpbijo`; ключ в extension/identity.json не меняется.

EXE, ZIP и `latest.json` с SHA-256 обоих пакетов публикуются вместе после успешных сборок. Popup проверяет GitHub API не чаще раза в 30 минут, кнопка «Проверить обновления» проверяет сразу. На Windows он скачивает EXE, на других системах и для старых релизов без EXE — ZIP. Скачивание не запускает установщик и не обновляет расширение в браузере.

Установщик автоматизирует только размещение файлов. Chrome на Windows [ограничивает прямую установку расширений вне Chrome Web Store](https://developer.chrome.com/docs/extensions/how-to/distribute): первое подключение и Reload остаются ручными. Полноценная установка и автообновления через Chrome Web Store — отдельная задача; публикация в магазине и подпись EXE в эту реализацию не входят.

Сборка установщика и оставшиеся ручные проверки описаны в [installer/windows/README.md](installer/windows/README.md).


## Разработка

Node.js >=22.12, `npm ci`, `npm test`, `npm run build`.

Результаты: extension-dist/ (загрузка в Chrome) и dist/extension/tvissn-extension.zip.

Автоматические тесты проверяют протокол/устаревшие команды, оба offscreen-runtime через имитацию RTC и Chrome RPC, обмен кодами, подтверждения, разрыв соединения, работу виджета и выбор плееров. Они не заменяют проверку настоящего ICE/NAT между двумя сетями.

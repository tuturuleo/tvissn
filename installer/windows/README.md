# Windows installer

Исходник: `tvissn.iss`. Постоянный AppId и HKCU\Software\tvissn\ExtensionInstaller\InstallDir идентифицируют установщик и сохраняют выбранную папку. Реестр Chrome и профили браузера не используются. Установка только для текущего пользователя, без удаления каталога, служб, фоновых процессов и автоматического запуска браузера. Удаление расширения остаётся в Chrome, файлов — вручную; деинсталлятор намеренно не создаётся.

## Локальная сборка

Нужны готовые зависимости проекта, Node.js и локальный Inno Setup 6 (в CI используется 6.4.3). Скрипт ничего не скачивает. На Windows в PowerShell из корня проекта:

```powershell
npm test
npm run build
$env:ISCC_PATH = "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe"
npm run build:installer:windows
Get-FileHash .\dist\extension\tvissn-extension-setup.exe -Algorithm SHA256
Get-Content .\dist\extension\latest.json
```

ISCC_PATH можно не задавать, если ISCC.exe доступен через PATH или стандартный каталог Inno Setup 6. Сборка сверяет release.json, manifest.json, ключ, SHA-256 ZIP и каждый файл ZIP с extension-dist. Результат: `dist/extension/tvissn-extension-setup.exe`. В latest.json сохраняются прежние поля и добавляется `windowsInstaller: {fileName, sha256}`. В workflow версия создаётся один раз на Ubuntu; Windows получает готовый пакет артефактом и компилирует EXE из него. Публикация ждёт обе сборки и проверяет контрольные суммы.

## Ручная проверка на Windows

Эти проверки требуют Windows, Chrome и настоящего компилятора Inno Setup. Не заменяйте их проверкой скрипта на другой ОС.

1. Под обычной учётной записью запустите EXE. Убедитесь, что UAC не запрашивается, путь по умолчанию — `%LOCALAPPDATA%\tvissn\extension`, финальный экран показывает полный путь. В Chrome включите режим разработчика, Load unpacked, выберите этот путь. Проверьте ID `fkohpgglbodngaicfehkgdojlbgpbijo`, задайте имя и настройки.
2. Соберите следующую версию: измените локально release.json на большую корректную Chrome-версию, выполните `npm run build` и `npm run build:installer:windows`. Запустите EXE. Он должен предложить прежнюю папку. После Reload без удаления расширения проверьте новую версию, тот же ID и настройки. Проверьте SHA-256 установленных файлов против extension-dist. Верните release.json после проверки.
3. Отдельно под чистой учётной записью (чтобы не было сохранённого пути) распакуйте старый ZIP в `%USERPROFILE%\My Extensions\tvissn old`, подключите его через Load unpacked, сохраните настройки. Создайте рядом `my-notes.txt` и подпапку с контрольным файлом. При первом запуске нового EXE выберите эту точную папку. Проверьте, что дополнительная подпапка extension не создаётся, посторонние файлы целы, а после Reload сохранились ID и настройки. Следующий EXE должен предложить этот путь.
4. Запретите запись одного из файлов пакета ACL для тестовой учётной записи, запустите обновление. Установка должна завершиться ошибкой, без экрана успеха; восстановите права и повторите. Проверка SHA-256 после записи также должна исключать успех при пропущенном или неверно записанном файле.
5. В popup на Windows проверьте скачивание EXE и соответствующую инструкцию, на macOS/Linux — ZIP. Для старого релиза без EXE Windows должна получить ZIP. Установщик не должен запускаться сам.

EXE не подписан; фактическую компиляцию, отображение длинного пути на финальном экране и поведение ошибок записи необходимо проверить на Windows перед выпуском.
